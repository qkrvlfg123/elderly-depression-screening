
# 사랑방 자서전 — 우울 위험 선별 AI

> 매일 질문 하나에 말로 답하는 녹화 한 번으로 — 자서전이 쌓이고 · 건강 신호가 감지되고 · 또래와 연결됩니다.

**사랑방 자서전**은 고령층이 오늘의 질문에 구술로 답하면 그 영상이 자동으로 숏폼·자서전으로 제작되고, 발화 텍스트에서 **우울 신호를 비의료적으로 관찰**해 가족에게 전달하는 시니어 헬스케어 서비스입니다.

이 레포지토리는 그중 **Data Analyst(DA) 파트 — 우울 위험 선별 AI**의 코드를 담고 있습니다. 데이터 정리부터 학습, 화자 단위 평가, 추론 API 서버까지의 파이프라인입니다.

## 📊 평가 방식

- **화자 단위 분할**: 한 화자의 텍스트는 학습·평가 중 한 곳에만 들어갑니다. test는 화자 8:2 분할(시드 42)의 20%인 1,164명이고, 분할은 `results/split.csv`에 고정되어 있습니다.
- **발표 최종본 (서빙 모델)**
  - 당시에는 val을 따로 두지 않았고, 모델마다 test 점수가 가장 높은 epoch, 학습한 여러 모델 중 test 점수가 가장 높은 4개 조합을 골랐습니다. 그래서 이 모델의 test AUROC는 낙관적인 값입니다.
  - 점수 보정(0.50–0.78 → 0–1)과 등급 기준(0.4 / 0.5)은 시연 문장으로 정한 값이라 test를 보고 정하지 않았습니다. 이 규칙을 test에 한 번 적용한 결과는 그대로 쓸 수 있습니다.
- **최종본 재현**: 같은 데이터·분할·설정으로 4모델을 다시 학습하고 epoch마다 test 예측을 저장했습니다. 미리 정한 규칙(마지막 epoch 5)의 값과, 당시 방식(test로 epoch 선택)의 값을 함께 보고합니다.
- **val 기반 파이프라인**: 남은 4,655명을 train 4,073 / val 582로 다시 나누고 epoch·앙상블 구성원·임계값을 val로만 정한 뒤 test를 한 번 평가했습니다.
  - 관찰(🟡 이상) 임계값: val 재현율 0.80 이상을 만족하는 가장 높은 값
  - 상담 권유(🔴) 임계값: val 특이도 0.80 이상을 만족하는 가장 낮은 값. 🔴는 가족 알림으로 이어지고, 기획서도 임계치 초과 시에만 알림을 보내 알림 피로를 막도록 되어 있어서 비위험군 오경보를 20% 이내로 제한했습니다. 이 기준은 처음 test 평가(재현율 기준만 사용)를 본 뒤 추가했습니다. AUROC는 임계값과 무관해 영향이 없습니다.
- **교차검증**: 전체 5,819명을 화자 단위 5-fold로 나누고, fold마다 모델을 새로 학습합니다. 각 fold의 학습 화자 중 12.5%를 epoch 선택용 val로 씁니다.
- **신뢰구간**: test 화자를 2,000회 재표집한 부트스트랩 95% 구간입니다.
- **청킹**: 문장부호(. ! ?) 경계를 유지해 앞에서부터 청크를 만들고, 화자 확률은 청크 확률의 평균입니다. 한국어는 토큰당 약 2자라서 청크가 토큰 상한 안에 들어가도록 맞췄습니다.
  - 최종본: KoBigBird 6,000자 × 최대 5청크(3,072토큰), KLUE 계열 800자 × 최대 8청크(512토큰)
  - val 기반 파이프라인: KoBigBird 2,000자 × 최대 5청크(1,024토큰), KLUE 계열은 최종본과 같음

### 보고 수치 정리

모두 같은 test 1,164명 기준입니다.

| 수치 | 무엇인가 | test로 고른 것 |
|------|------|------|
| 0.674 | 실험 예측 4개(당시 실험 그룹 T·U2)의 평균. 발표 보고 수치 | epoch, 4개 조합 |
| 0.661 | 배포된 최종본 가중치 4개의 평균 (서빙 모델) | epoch, 4개 조합 |
| 0.659 | 재현 학습, test로 epoch 선택 | epoch |
| **0.641** | **재현 학습, epoch 5 고정** | 없음 (조합은 최종본을 따름) |
| 0.625 | val 기반 파이프라인 | 없음 |

- 0.674와 0.661의 차이: 발표 수치는 실험 때 저장한 예측 파일로 계산했고, 배포된 가중치는 따로 학습한 것입니다. 모델별로 보면 KLUE-RoBERTa_888이 0.646(실험 예측)과 0.587(배포 가중치)로 가장 크게 다릅니다. 배포 가중치의 test 예측은 당시 남긴 `pred_FINAL_*` 파일과 소수 넷째 자리까지 같습니다.
- 0.661과 0.641의 차이(약 0.02)는 test로 epoch과 조합을 고른 효과에 가깝습니다. 재현에서 epoch 선택만으로 0.018이 오릅니다.
- 0.641과 0.625의 차이(약 0.015)는 학습 설정(긴 입력·KSSDS·5 epoch)과 학습 화자 수(4,655명 대 4,073명) 차이입니다. 이 차이는 통계적으로 뚜렷하지 않습니다.
- 이전 버전 README의 5-fold/10-fold 수치(0.675/0.672)는 재학습 없이 같은 예측을 나눠 평균한 값이라 교차검증이 아닙니다. 41개 모델 중 4개 앙상블이라는 설명과 달리, 당시 레포 코드는 6개를 학습하고 2개를 저장했습니다.
- 정리하면 이 모델의 텍스트 단독 성능은 AUROC 0.62–0.64 수준이고, 답변 1개 분량 입력에서는 약 0.60입니다.

## 🧩 파이프라인

```
JSON 원본 (AI-Hub 71703)
      │
      ▼  00_make_speakers_csv.py     화자별 통합 + PHQ-2/GAD-2·인구통계 정리
speakers.csv
      │
      ▼  01_preprocess_kssds.py      KSSDS 문장 분리 → speakers_clean_kssds.csv (최종본 학습 입력)
      │
      ├─ 08_reproduce_final.py       최종본 4모델 재학습 (epoch별 test 예측) → results/repro_final4.json
      ├─ 09_final_serving.py         최종본 서빙 구성(ensemble.json) 작성 + test 평가 → results/final_serving.json
      ▼  04_serve_api.py             FastAPI 앙상블 서버 (위험도 → 보정 → 행복지수 → 3단계)
POST /predict → {"risk_score": 0.32, "happiness_index": 68, "grade": "안정", ...}

  val 기반 파이프라인 (speakers.csv)
  02_train_ensemble.py → 06_evaluation.py → 07_input_length.py
  05_cross_validation.py             화자 단위 5-fold, fold마다 재학습
```

`src/common.py`의 `chunk_text` / `aggregate`를 학습(02), 교차검증(05), 서빙(04), 최종본 평가(09)가 함께 씁니다.

## 📌 참고 · 한계

- 우울 라벨은 **PHQ-2 유사 선별 문항**이며, 의학적 진단이 아닌 **관찰·연결**이 목적입니다. (자서전/회고가 주 기능, 정서 관찰은 보조 기능)
- 원본 데이터(`speakers*.csv`)와 학습된 모델 가중치는 **AI-Hub 라이선스 및 용량 문제로 포함하지 않습니다.** AI-Hub에서 데이터셋 71703을 받아 화자 단위로 통합한 뒤 실행하세요.
- 서빙 모델은 test로 epoch과 조합을 고른 모델이라, test AUROC 0.661은 낙관적인 값입니다. 미리 정한 규칙으로 재학습한 값은 0.641입니다. 같은 test를 계속 썼기 때문에 새로운 화자에서의 성능은 별도 데이터로 확인해야 합니다.
- 답변 1개 분량(800자) 입력에서는 AUROC 0.604이고, 상담 권유 등급은 약 24%를 표시하는 대신 위험군의 약 34%만 잡습니다.
- 점수 보정 구간(0.50–0.78)과 등급 기준은 시연 문장으로 정한 값이라 근거가 약합니다.
- 구술 데이터는 과거 회상 중심이라 현재 우울 예측에 구조적 한계가 있으며, 향후 **음성·표정 멀티모달**로 확장 예정입니다.
