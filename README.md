
# 사랑방 자서전 — 우울 위험 선별 AI

> 매일 질문 하나에 말로 답하는 녹화 한 번으로 — 자서전이 쌓이고 · 건강 신호가 감지되고 · 또래와 연결됩니다.

이 레포지토리는 그중 **Data Analyst(DA) 파트 — 우울 위험 선별 AI**의 코드를 담고 있습니다. 데이터 정리부터 학습, 화자 단위 평가, 추론 API 서버까지의 파이프라인입니다.

## 📊 평가 방식

- **화자 단위 분할**: 한 화자의 텍스트는 train·val·test 중 한 곳에만 들어갑니다. test는 이전 버전 평가셋과 같은 화자 1,164명(위험군 258명)이라 직접 비교할 수 있습니다. 나머지 4,655명을 라벨 계층화로 train/val로 나눴습니다. 분할은 `results/split.csv`에 고정되어 있습니다.
- **val로만 선택**
  - epoch: 구성마다 3 epoch을 학습하고 val AUROC가 가장 높은 epoch의 가중치를 씁니다.
  - 앙상블: val AUROC 순으로 정렬한 뒤 상위 k개 평균 중 val AUROC가 가장 높은 k를 고릅니다.
  - 임계값 두 개
    - 관찰(🟡 이상): val 재현율 0.80 이상을 만족하는 가장 높은 값입니다. 알림이 없는 등급이라 위험군을 놓치지 않는 쪽으로 정했습니다.
    - 상담 권유(🔴): val 특이도 0.80 이상을 만족하는 가장 낮은 값입니다. 🔴는 가족 알림으로 이어지고, 기획서도 임계치 초과 시에만 알림을 보내 알림 피로를 막도록 되어 있어서, 비위험군 오경보를 20% 이내로 제한했습니다.
    - 고정 임계값 0.5 결과도 참고용으로 같이 보고합니다.
    - 상담 권유 기준은 처음 test 평가(재현율 기준만 사용)를 본 뒤, 위 알림 정책을 근거로 추가했습니다. AUROC는 임계값과 무관해 영향이 없습니다.
- **test는 한 번만**: 위에서 정한 앙상블과 임계값으로 test를 평가합니다. 신뢰구간은 test 화자를 2,000회 재표집한 부트스트랩 95% 구간입니다.
- **교차검증**: 전체 5,819명을 화자 단위 5-fold로 나누고, fold마다 모델을 새로 학습합니다. 각 fold의 학습 화자 중 12.5%를 epoch 선택용 val로 쓰고, held-out fold는 평가에만 씁니다.
- **청킹**: 문장부호(. ! ?) 경계를 유지해 앞에서부터 청크를 만들고, 화자 확률은 청크 확률의 평균입니다. KoBigBird는 2,000자 × 최대 5청크(1,024토큰), KLUE 계열은 800자 × 최대 8청크(512토큰)입니다. 한국어는 토큰당 약 2자라서 청크가 토큰 상한 안에 들어가도록 맞췄습니다.

### 입력 길이별 test 성능 (답변 1개 분량)

학습 입력은 화자 한 명의 답변 여러 개(중앙값 17개)를 이은 텍스트로, 중앙값이 약 11,800자입니다. 서비스 입력은 하루 답변 1개이고, 데이터에서 답변 1개는 중앙값 약 780자(중간 50%가 400–1,600자)입니다. test 텍스트를 앞에서부터 N자로 잘라 같은 앙상블로 다시 예측했습니다(`src/07_input_length.py`, 재학습 없음).

| 입력 | AUROC (95% CI) | 🔴 상담 권유 비율 | 🔴 재현율 · 정밀도 | 🟡 관찰 이상 비율 · 재현율 |
|------|:---:|:---:|:---:|:---:|
| 앞 400자 | 0.566 (0.525–0.605) | 22.0% | 0.287 · 0.289 | 73.8% · 0.798 |
| **앞 800자 (답변 1개)** | **0.587 (0.547–0.624)** | **25.1%** | **0.310 · 0.274** | **77.0% · 0.860** |
| 앞 1,600자 | 0.615 (0.576–0.655) | 14.3% | 0.221 · 0.343 | 82.4% · 0.919 |
| 전체 | 0.625 (0.588–0.663) | 8.8% | 0.136 · 0.343 | 81.4% · 0.922 |

- 표의 등급 비율은 서빙 임계값(관찰 0.388, 상담 권유 0.611)으로 계산했습니다.
- 입력이 짧아지면 점수 분포가 달라집니다. 전체 길이 val로 정한 임계값(0.425 / 0.553)을 800자 입력에 쓰면 🔴 비율이 23%에서 41%로 올라갑니다. 그래서 서빙 임계값은 앞 800자로 자른 val에서 같은 규칙으로 다시 정했습니다.
- 서비스에서 기대할 성능은 800자 행에 가깝습니다. 한 사람의 답변 여러 개를 모아 판단하면 학습 조건(전체)에 가까워집니다.

### 이전 보고 수치와의 비교

이전 버전은 같은 20%(1,164명)로 epoch 선택, 모델 순위, 앙상블 구성을 모두 정한 뒤 그 20%에서 AUROC 0.674를 보고했습니다. 5-fold/10-fold 수치(0.675/0.672)는 재학습 없이 같은 예측을 나눠 평균한 값이라 교차검증이 아닙니다. 41개 모델 중 4개 앙상블이라는 설명과 달리, 코드는 6개를 학습하고 2개를 저장했습니다.

이전 작업에서 남은 예측 파일 45개(레포 밖 보관, 모두 이번 test와 같은 1,164명)로 같은 지표를 다시 계산했습니다.

| | test AUROC |
|------|:---:|
| 이전 개별 모델 45개 | 0.567–0.651 (중앙값 0.624) |
| 이전 개별 최고 (KoBigBird_1234_f) | 0.651 |
| 이전 45개 전부 평균 (구성원 선택 없음) | 0.653 |
| 이전 최종 4개 평균 (보고 수치) | 0.674 (95% CI 0.637–0.712), 재현됨 |
| **이번 앙상블** | **0.625 (95% CI 0.588–0.663)** |

- 0.674와 0.653의 차이(약 0.02)는 45개 중 test 점수가 좋은 4개를 test를 보고 고른 데서 나옵니다.
- 0.653과 이번 0.625의 차이(약 0.03)에는 여러 원인이 섞여 있습니다.
  - 이전에는 모델마다 test 점수가 가장 높은 epoch을 골랐습니다.
  - 이전에는 val을 따로 두지 않아 학습 화자가 582명 더 많았습니다(4,655명 대 4,073명).
  - 이전 평균은 45개, 이번은 4개입니다.
  - 이전에는 KSSDS 문장 분리 텍스트와 다른 청크·epoch 설정을 썼습니다.
- 두 결과의 신뢰구간은 겹칩니다. 이전 모델의 실제 성능은 0.65 안팎이었고, 그중 일부는 평가셋 선택 효과였습니다.

### 관찰

- 모든 구성에서 최적 epoch이 마지막(3)이었습니다. 3 epoch이 부족했을 수 있습니다.
- KLUE-RoBERTa_888은 무작위 수준(0.51–0.53)으로, 같은 학습률·설정에서 학습이 거의 되지 않았습니다.
- val이 582명이라 val AUROC의 변동이 큽니다. 상위 k 앙상블의 val 이득도 0.596 → 0.598로 작았습니다.

## 🧩 파이프라인

```
JSON 원본 (AI-Hub 71703)
      │
      ▼  00_make_speakers_csv.py     화자별 통합 + PHQ-2/GAD-2·인구통계 정리
speakers.csv
      │
      ├─ (선택) 01_preprocess_kssds.py   KSSDS 문장 분리. 원본에 문장부호가 충분해(약 57자당 1개) 이번 결과에는 쓰지 않음
      │
      ▼  02_train_ensemble.py        화자 단위 분할 → 6구성 학습, val로 epoch 선택
      │                                → saved_models/<구성>/, 화자별 val/test 예측 (레포 미포함)
      ▼  06_evaluation.py            val로 앙상블·임계값 결정 → test 1회 평가
      │                                → results/experiments.csv, saved_models/ensemble.json
      ▼  07_input_length.py          서비스 입력 분량(앞 800자) val로 서빙 임계값 결정, 입력 길이별 test 성능
      │                                → results/input_length.csv, saved_models/ensemble.json
      ▼  04_serve_api.py             FastAPI 앙상블 서버 (위험도 → 행복지수 → 3단계)
POST /predict → {"risk_score": 0.32, "happiness_index": 68, "grade": "안정", ...}

  └─ 05_cross_validation.py         화자 단위 5-fold, fold마다 재학습
```

`src/common.py`의 `chunk_text` / `aggregate`를 학습(02), 교차검증(05), 서빙(04)이 함께 씁니다.

## ▶️ 실행

```bash
pip install -r requirements.txt

# 0) JSON 원본 → 화자별 통합 CSV (AI-Hub 71703 데이터 필요). 레포 루트에 speakers.csv 로 둔다
python src/00_make_speakers_csv.py --json-dir ./json --out speakers.csv

# 2) 구성별 학습 (RTX 4070 기준 KoBigBird 구성당 약 73분, KLUE 계열 약 18분)
python src/02_train_ensemble.py --csv speakers.csv

# 6) val로 앙상블·임계값 선택 → test 1회 평가
python src/06_evaluation.py --csv speakers.csv

# 7) 서빙 임계값 결정(앞 800자 val) + 입력 길이별 test 성능. 06 다음에 실행
python src/07_input_length.py --csv speakers.csv

# 5) 화자 단위 5-fold 교차검증 (구성당 약 6시간)
python src/05_cross_validation.py --csv speakers.csv --config KoBigBird_1234_f

# 4) API 서버 (saved_models/ensemble.json 의 구성원과 임계값을 사용)
python src/04_serve_api.py --models ./saved_models
# → POST http://localhost:8000/predict  {"text": "..."}
```

02와 05는 이미 예측 파일이 있는 구성·fold를 건너뛰므로 중단 후 다시 실행하면 이어서 진행합니다.

서빙 등급은 07이 앞 800자로 자른 val에서 정한 임계값을 씁니다. 위험도가 0.611 이상(val 특이도 0.80 지점)이면 상담 권유, 0.388 이상(val 재현율 0.80 지점)이면 관찰, 그 아래는 안정입니다. 응답 필드는 이전 명세와 같습니다(`raw_score`는 보정을 없애 `risk_score`와 같은 값). 추론 API 입출력 형식은 [`docs/API명세.md`](./docs/API명세.md) 참고.

## 📌 참고 · 한계

- 우울 라벨은 **PHQ-2 유사 선별 문항**이며, 의학적 진단이 아닌 **관찰·연결**이 목적입니다. (자서전/회고가 주 기능, 정서 관찰은 보조 기능)
- 원본 데이터(`speakers*.csv`)와 학습된 모델 가중치는 **AI-Hub 라이선스 및 용량 문제로 포함하지 않습니다.** AI-Hub에서 데이터셋 71703을 받아 화자 단위로 통합한 뒤 실행하세요.
- 텍스트 단독 성능은 AUROC 약 0.61–0.63 수준이고, 답변 1개 분량(800자) 입력에서는 0.587입니다. 상담 권유 등급은 표시 인원을 약 25%로 묶는 대신 위험군의 약 31%만 잡습니다.
- 구술 데이터는 과거 회상 중심이라 현재 우울 예측에 구조적 한계가 있으며, 향후 **음성·표정 멀티모달**로 확장 예정입니다.
